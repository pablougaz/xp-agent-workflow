# ai-workflows

Personal monorepo of independently installable APM workflow packages.

## Packages

### `base-workflows` 0.2.0

General cross-harness skills:

- `remind-me`
- `start-worktree`
- `clean-worktree`

Source: [`packages/base-workflows`](packages/base-workflows)

### `xp-agent-workflow` 0.3.1

Reusable XP and Pensieve planning workflow:

- XP/TDD development instructions
- Pensieve planning conventions
- `xp-brainstorm-feature`
- `xp-plan-feature`
- `xp-review-feature-plan`
- `xp-review-refactoring`
- `xp-update-feature-status`

Source: [`packages/xp-agent-workflow`](packages/xp-agent-workflow)

The XP package retains its independent history: `v0.1.0` identifies the
original root package release, and version `0.3.1` is the current package
version.

Keep repo-specific commands, architecture, ports, services, and test names in
each consuming repo's own `AGENTS.md` or equivalent harness file.

## What Is Pensieve?

`pensieve/` is the workspace memory folder for agent-assisted development. The name comes from the Harry Potter memory storage/retrieval device: it is where the agent and human keep feature plans, brainstorm notes, story breakdowns, work status, and durable progress context between sessions.

Many repos might call this folder `plans/`, `docs/`, or `work/`. This workflow uses `pensieve/` because it is descriptive for agent memory and unlikely to collide with an existing project directory.

## Versioned Releases

Packed bundles are committed under `releases/` so every published version is
visible and independently installable:

```text
releases/
├── base-workflows/
│   ├── base-workflows-0.1.0/
│   └── base-workflows-0.2.0/
└── xp-agent-workflow/
    ├── xp-agent-workflow-0.1.0/
    ├── xp-agent-workflow-0.2.0/
    ├── xp-agent-workflow-0.3.0/
    └── xp-agent-workflow-0.3.1/
```

Each bundle contains `plugin.json` plus an integrity lockfile generated by
`apm pack`. Release tags provide an additional immutable Git marker, but the
packed bundle is the tangible release artifact.

## Install Both Into a Project

Declare both packages in the consuming project's `apm.yml`:

```yaml
name: your-project
version: 0.1.0
dependencies:
  apm:
    - pablougaz/ai-workflows/releases/base-workflows/base-workflows-0.2.0
    - pablougaz/ai-workflows/releases/xp-agent-workflow/xp-agent-workflow-0.3.1
```

Then run:

```bash
apm install --target agent-skills
```

Skills deploy to `.agents/skills/`. The XP instruction files are staged for
compilation; run this when you want APM to merge them into the harness context:

```bash
apm compile --target codex
```

The packaged skills are namespaced with an `xp-` prefix so they can run alongside older hand-copied prompts:

```text
/xp-brainstorm-feature
/xp-plan-feature
/xp-review-feature-plan
/xp-review-refactoring
/xp-update-feature-status
```

The base skills are intentionally not XP-prefixed:

```text
/remind-me
/start-worktree
/clean-worktree
```

## Install Base Skills Globally

Install only the base package at user scope:

```bash
apm install \
  pablougaz/ai-workflows/releases/base-workflows/base-workflows-0.2.0 \
  --global \
  --target agent-skills
```

This makes the skills available from `~/.agents/skills/` to harnesses that
support the shared Agent Skills convention. Use APM to update the installation
rather than copying files between Claude, Codex, Cursor, or other harness
directories.

See [docs/workflow-usage.md](docs/workflow-usage.md) for the XP workflow
diagram and pilot guidance.

## Release a New Package Version

1. Change only the source package under `packages/<name>/`.
2. Bump `version:` in that package's `apm.yml`.
3. Run `apm lock`, `apm pack --dry-run --verbose`, and
   `apm audit --ci --no-policy` from the package directory.
4. Pack into the permanent release collection:

```bash
apm pack --force -o ../../releases/<package-name>
```

5. Install the new bundle into a scratch project and audit it.
6. Commit the source and generated bundle together.
7. Tag that commit as `<package-name>-v<version>`.

For example, releasing `base-workflows` 0.2.0 creates:

```text
releases/base-workflows/base-workflows-0.2.0/
```

For local validation before publishing, run from each source package:

```bash
apm pack --dry-run --verbose
apm audit --ci --no-policy
```
